# ADR 0020: Task worktree lease and immutable base

Status: Accepted for P2-02 · 2026-09-24

## Decision

- Extend the P0-06 Host-owned `@forge/workspace` manager rather than introduce another worktree owner. P2 task workspaces use a generated `forge/run/<workspace UUID>` branch; the source root and base ref must resolve to the same Git repository. Git receives separate argv entries and the existing empty hooks path. The branch name is generated by Forge and is never a Renderer string.
- Resolve the base commit and its Git tree before creating the worktree. Save both in the private ownership record along with the source common Git directory, run ID, runtime ID, owner token, branch and a preliminary snapshot exclusion policy. This is a **baseline reference**, not a deliverable CodeSnapshot. P2-09 will make the allowlisted change snapshot and actually apply exclusion rules to file content.
- The active write lease is represented by a random lease ID and monotonic epoch in the same Host-owned record. Acquisition is serialized per workspace before any awaited Git check; a concurrent request cannot obtain a second writer. The Host resource boundary checks lease ID and epoch before starting an Executor. `releaseLease` retains the worktree, requires the current lease ID and no active owned processes, and lets a later Attempt obtain a fresh ID with a larger epoch. Workspace disposal separately checks owned path/Git identity and active processes; quarantine retains the record. A restarted Host reports old-runtime workspaces as possible orphans but does not automatically reassign or delete them.
- Releasing the worktree does not force-delete its Forge branch. A future retention policy must verify ownership and whether it holds user-valued commits before removing it. No source working-tree change, stash, reset or merge is performed in P2-02.

## Scope and follow-up

P2-02 proves a real Git task branch, immutable base commit/tree and single-writer acquisition. It does not create a Run or Attempt. Full T046 write-Attempt integration is P2-05; T047 and T049 deliverable snapshot/path checks are P2-09; T050 target-head revalidation is P3-08. These original IDs remain `DEFERRED_VERIFICATION` in the trace manifest. T048 is covered at the workspace API boundary by strict base-hash validation, generated branch names, argv-only Git calls and malicious-ID/symlink tests; no arbitrary Git command interface exists.

The reference SQL contract includes `workspaces` and `workspace_leases`, but the current manager's ownership journal is a Host-private runtime artifact. The formal Run/Attempt state and transactionally acquired lease in the business database belong to P2-05. Until then, this implementation exposes no production Start command. This avoids treating an in-memory or journal-only lease as a distributed lock.

## Verification and risks

On macOS arm64, a real Unicode/space-path Git fixture created a task branch from the exact base commit/tree; two concurrent acquire calls yielded one lease; source HEAD/status stayed unchanged; worktree release removed only Forge's owned tree. Existing symlink, path traversal, active-process, orphan and Host cancellation tests remain in the suite. Windows x64, macOS Intel, packaged app, process crash during journal write and concurrent independent Host instances remain unverified. Git worktree is isolation from the user's working directory, not an execution sandbox.
