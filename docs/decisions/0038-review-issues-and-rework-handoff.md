# ADR 0038 · Review issue history and compact rework handoff

Date: 2026-09-24<br>
Status: Accepted for P3-03 under the Python Core and canonical P3 task map

## Decision

The Python Host owns Review execution, reports, issue history and rework handoffs. A user explicitly starts a Reviewer against an immutable DevelopmentHandoff; the Host rechecks the trusted active Git Project, latest Task snapshot, current model capability, enforced native read-only sandbox and P3-01 review copy. Electron Main continues to forward only a fixed, schema-validated Run command; Renderer has no filesystem, process, Codex or SQLite access. The Reviewer cannot auto-start a new developer Attempt, move the Task to Done or approve Verify/human acceptance.

An additive SQLite migration v17 introduces `review_jobs`, immutable `review_reports`, stable `review_issue_threads`, immutable per-attempt `review_issue_occurrences` and immutable `review_rework_handoffs`. The logical issue fingerprint uses Task, repository-relative path, basis and normalized reason; it deliberately omits line numbers so the same problem can retain its issueId after code moves. Different reasons or bases remain distinct. A new Review on a later snapshot adds an occurrence instead of a duplicate issue card. A complete approved/changes-requested report marks unmentioned older open issues `stale`, never `resolved` or `waived` by inference. Missing, invalid or stale Review output stays inconclusive or is rejected under ADR 0037. Review reports and occurrences cannot be updated or deleted. Rework handoff contains current contract/snapshot reference, stable blocking issue IDs and concise anchored findings; it does not copy development chat or provider session internals.

The read-only specification's `contracts/schema.sql` describes a full future `review_issues` table connected to generalized Runs and Artifacts. The current production database already has a different incremental schema and does not yet have generic Review Runs/Artifacts. Migration v17 preserves its semantics through separate job/report/thread/occurrence tables and foreign keys to existing Project/Task/development Run/CodeSnapshot. It does not rewrite or drop any historical table or alter the read-only contract. Generalized artifact and workflow relationships must be reconciled when their owner tasks are implemented; this is a documented production-schema mapping, not a claim of byte-identical DDL.

The Host persists a Review job before launching the adapter. On Host restart, unfinished jobs become `interrupted` and historical review copies are reported as orphans, with no PID-only kill or silent reuse. Normal shutdown requests cancellation of owned Reviewer processes and waits before the process controller disposes remaining owned children. The UI shows real job state, report outcome, issue occurrence history and source anchors. `approved` here means the Review report passed its own schema and semantic gate; Verify and final human acceptance remain separate.

## Evidence and limits

`python/tests/test_review_issues.py` uses real SQLite v17, Git worktrees, P1 approved Task data and fixed snapshot refs. It verifies same issueId over multiple Reviewer attempts and two snapshots, retained occurrence history, old snapshot rejection, stale state after a later approved Review, compact handoff, report immutability and restart/independent Python Host JSON-RPC reads. `FORGE_VERTICAL_REVIEW_ONLY=1 FORGE_VERTICAL_MODEL=gpt-6-sol node scripts/smoke-python-vertical-live.mjs` completed a real Electron Renderer→Main→Python Host→Codex development Run, then a separate read-only Codex Review; a retry with the same idempotency key returned the same Review job. The returned structured report was `approved` with zero issues for that fixture, bound to its CodeSnapshot, and source Git stayed clean. The issue-dedup fixture uses constructed Review results to exercise deterministic persistence; the live provider run did not itself produce a blocking issue. Screenshot: `output/playwright/p3-03-python-desktop-review-1440x900.png`.

P3-06 owns actual bounded return-to-Develop orchestration and new Attempt scheduling. P3-07 owns human risk waiver; `waived` is not `pass`. Windows x64, macOS Intel, packaged Python/Codex/sandbox, real user-data v16→17 upgrade and unexpected Host death while Review is active remain **UNVERIFIED**. No new dependency, credential, network service or user-repository mutation was introduced.
