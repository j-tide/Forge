# ADR 0039 · Python project command verifier

Date: 2026-09-24  
Status: Accepted for canonical P3-04 on the Python Core development path

## Decision

The Python Host owns deterministic project verification. It accepts only a fixed `run.verifyStart` payload naming the trusted active Project, approved Task's completed development Run, current immutable CodeSnapshot, check kind, approved CommandPreset ID and idempotency key. Renderer cannot send an executable, argv, cwd, environment, report path or SQL. Electron Main validates the fixed TypeScript command and forwards versioned JSON-RPC over stdio; it never runs a project command. The production implementation is `python/src/forge/verifier_project.py`, corresponding to the read-only task map's `plugins/verifier-project` capability. The separate plugin registry does not yet advertise a Verifier contribution; P4 owns generalized plugin installation/registration. This Host-owned implementation does not claim a third-party plugin API is ready.

The Host rechecks Project trust, canonical Git root, frozen RunConfig/Handoff/CodeSnapshot, latest Task snapshot, Environment membership, current script hash, CommandPreset revision and approval digest. Only the previously approved executable plus argv run, with no shell and a minimal inherited environment. Named environment/secret references are rejected until a resolution policy exists. A missing declared test script with no preset becomes `not_configured` and `needsHuman=true`; any declared test without an approved preset is rejected. Project trust and preset approval authorize local project scripts, which can execute arbitrary code as the local user. The verifier does **not** claim sandbox confinement of project scripts.

Execution uses a Host-owned detached Git worktree pinned to the snapshot commit/tree, never the source worktree or Developer workspace. The ProcessController owns the process group, enforces the approved timeout and confirms descendants stopped before completion. A dedicated `dispose_disposable` path removes only an identity-verified, runtime-owned detached verifier copy after all owned processes stop, including build output. It cannot accept an arbitrary directory path. Unknown or failed ownership leaves the copy for diagnosis rather than deleting a user worktree. Host shutdown cancels in-flight checks; interrupted jobs are marked on restart, and historical orphan process/workspace records are reported without PID-only automatic killing.

Additive SQLite migration v18 creates `verifier_jobs`, immutable `verifier_reports` and immutable generated stdout/stderr artifacts. Report identity binds Project, Task, development Run, CodeSnapshot, kind, Preset revision and approval hash. Job start is idempotent by key. A process exit code of zero is required for `passed`; text saying PASS cannot override a nonzero exit. Timeout, process-tree uncertainty and infrastructure errors cannot pass. Output is bounded, redacted before persistence, labelled when truncated, returned by opaque artifact UUID and project scope, and fixed to `text/plain`; there is no external artifact path import. Original exit code, duration, status and bounded redacted stdout/stderr remain available as evidence. P3-05 owns mapping these command reports to per-criterion acceptance statuses; a passed command does not set a Task to Done.

The read-only reference `contracts/schema.sql` describes generalized `verification_results` and `artifacts` for the eventual acceptance system. Existing production schema has incremental Run/Handoff tables; v18 adds narrow tables without rewriting historical data or changing the reference source. The report/criterion mapping is deferred to P3-05. Canonical T057's arbitrary external report-file import/root/MIME gate needs the generalized Artifact Store in P3-11; the current narrower UUID-only evidence API rejects external paths but does not claim that full test passed. T059 (acceptance click against stale snapshot) is owned first by P3-07, and T060 (idempotent merge operation) by P3-08. All retain their original Test IDs and P3-04 references as `DEFERRED_VERIFICATION`.

## Evidence and limits

`python/tests/test_verifier_project.py` runs real Git, SQLite and owned Python subprocesses on macOS arm64. It verifies pass, nonzero exit with PASS text, timeout, redacted evidence, isolated build output, immutable reports, restart durability, not-configured tests, stale snapshot/invalid paths, no source-repo changes and independent Python Host JSON-RPC commands. A real Electron Renderer→Main→Python Host→Codex development run created snapshot `ca377444-d54a-4b09-92cf-4b5c07f2a593`; an explicitly approved Node test preset then produced verification `295339f0-1ef1-4242-b06e-8626419a2924`, `passed` with exit code 0, while source Git remained clean. This is deterministic command verification, not final AC acceptance, automatic rework or Task Done.

No new third-party dependency, install script, credential store, local TCP server or Renderer capability was added. Actual existing user database v17→18 upgrade, Windows x64, macOS Intel, packaged Python/Node/Git paths, hard Host crash cleanup, full report-file formats beyond stdout/stderr and malicious project-script containment remain **UNVERIFIED**. This task does not execute commands against a user's existing repository.
