# ADR 0043 · Immutable delivery record and explicit local merge

Date: 2026-09-24<br>
Status: Accepted for P3-08 on the Python Core path

## Decision

The Python Host is the sole owner of delivery and Git merge operations. An accepted current CodeSnapshot is required before it may freeze a `DeliverySummary`. The summary records the approved Contract hash/revision, all Development Attempt Run IDs, the final immutable snapshot/commit/base, Review and Verify report IDs, per-criterion human decisions, explicit advisory waivers, unresolved accepted risks, final human decision and timestamps. No formal Plan has been implemented, so the Plan field says `not_configured`. The summary is immutable and keyed by the final acceptance decision. SQLite migration v22 adds only this record and a separate `merge_operations` intent table; historical tables and user data are not reset or rebuilt.

Done remains a final human acceptance projection. It does not imply a merge, push, release or deployment. The task detail shows delivery status separately. A merge requires a second deliberate UI checkbox and a native Electron confirmation dialog. The fixed Renderer bridge accepts only delivery/target/snapshot IDs, target branch and expected target HEAD; Electron Main checks the source, validates the command and displays the dialog but does not run Git or write SQL. The Python Host rechecks Project Trust and the current accepted snapshot, verifies the Forge snapshot ref, target branch, clean checkout and exact base revision. A moved target requires a new validated snapshot; it never reuses the old Review/Verify approval to merge. Non-Git or unknown target branch is unavailable, with no implicit initialization.

Host writes a durable, unique merge operation intent before touching Git. It first merges in a Forge-owned detached worktree at the expected target HEAD with Git hooks disabled; conflicts remain in that disposable workspace and do not modify the user's checkout. If the candidate is a two-parent merge with exactly the expected target and snapshot commits, Host applies it to the clean, checked-out local target with `git merge --ff-only`. It never force-merges, resets, stashes, pushes or deploys. A repeated operation key returns its prior receipt; after a crash between Git update and SQLite receipt, Host inspects the exact HEAD/parent commits and marks that intent merged, while ambiguous outcomes remain `unknown` and cannot be reported successful. A different key cannot create a second merge for the same delivery and target. Git commands use executable plus argv arrays and bounded timeouts. Temporary worktree cleanup is scoped to the operation ID; unresolved orphan worktrees are reported for P3-09 reconciliation, never globally pruned.

This first local merge path requires the target branch to be currently checked out and the source working tree to be clean. That constraint avoids updating a ref underneath another checkout. It is an explicit product limitation shown as a blocker, not a claim that all cross-platform or concurrent external Git cases are solved. Rechecking HEAD before apply plus fast-forward-only prevents a stale target from silently receiving the old snapshot; Git and SQLite still do not share one atomic transaction. A concurrent external Git writer during the final Git command is a remaining race to diagnose from the durable intent. The bounded local Git operation currently runs on the Python Host thread because its SQLite connection is thread-bound; Desktop suspends its heartbeat probe for this long request. General multi-request concurrency for delivery operations remains future work. Remote merge/push and installer packaging are outside this task.

## Evidence and limits

Disposable real Git/SQLite tests cover accepted delivery content, initial target, one two-parent merge, duplicate idempotency key, Host restart after Git success but before receipt, changed acceptance evidence invalidating Done, target advancement refusal with unchanged source, and actual Host JSON-RPC without an Executor. TypeScript contracts reject force/push/actor/shell fields; Vue tests require explicit checkbox and hide merge on drift. An authenticated Electron→Python Host→Codex development/Verify/Review/final acceptance run exercised the native dialog cancel path (no operation), then explicit UI merge to local `main`, resulting in exactly one two-parent commit and a clean working tree; screenshot `output/playwright/p3-08-python-desktop-merged-1440x900.png` was inspected. Full IDs and quality results belong in implementation status. T056/T058 verifier and T059 stale acceptance evidence remain from earlier tasks; T050 target drift and T060 merge idempotence are exercised here. T057 generic external Artifact import remains deferred to P3-11. Windows x64, macOS Intel, installed app bundles, signing and current-user existing DB v21→22 remain unverified.
