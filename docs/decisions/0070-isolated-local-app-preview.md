# ADR 0070 · Isolated local application preview

Status: Accepted for P6-03 (2026-09-25).

Forge's trusted Vue management window must never render an untrusted project app in its own `webContents`. A fixed `openAppPreview` Desktop bridge accepts one explicit URL. Main validates it again and accepts only `http://127.0.0.1:<non-default-port>/…`; it starts no project script, proxy, remote server, or Host command. The selected exact origin is the only allowed network destination for that preview window, including its subresources and WebSocket requests. This first version does not support external, LAN, HTTPS, or `file:` previews.

Each preview is a separate `BrowserWindow` and ephemeral session with no preload, Node integration, Forge bridge, webview or permission grant. Sandbox, context isolation and web security remain enabled. Main denies new windows, cross-origin navigation, downloads and JavaScript dialogs. Preview windows close with their management window. All Host IPC still checks the exact trusted management `webContents` and main frame; the preview's separate identity cannot pass. A project page cannot access arbitrary Forge IPC, and the Renderer cannot grant a new origin by itself. This is an isolation boundary for management capabilities, **not** a guarantee that untrusted local web content is harmless to the OS or other browser processes.

Code browsing uses only the bounded, redacted, Host-captured Run diff already persisted in SQLite. The UI selects a recorded changed-file patch when its exact marker exists; otherwise it says that an individual patch is unavailable and retains the full read-only diff. It does not access live source files, run scripts, or turn text into HTML. Private-key blocks are now redacted from Run observations/diff and rejected by the bounded Artifact import path.

Real macOS arm64 Electron smoke loaded a disposable localhost HTML page, found no `window.forge`, `require`, `process`, `ipcRenderer` or preload, confirmed distinct `webContents`, blocked `file:` navigation, cross-origin HTTP/WebSocket and `window.open`, and kept the Forge management UI alive. The actual preview window preferences had `disableDialogs: true`; invoking `alert()` from Playwright emitted a Chromium dialog event after automatic suppression and caused an automation protocol error, so this specific popup path is not claimed as a passing E2E assertion. The browser window and session configuration is covered by the real preference readback; broader native file chooser and print behavior remain for P6-09. No user project code or paid model was run.

T082 and the tested `file:`/new-window part of T083 have real evidence. Full T083 remains deferred because native dialog paths were not all exercised. T081 requires a scoped multi-ref credential broker that does not yet exist, T084's export confirmation belongs to P6-04, and T085's complete Project/Profile/node/plugin permission intersection belongs to P6-09. Their original Test IDs remain `DEFERRED_VERIFICATION`; the phase/release gate may not treat them as passed.
