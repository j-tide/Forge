# ADR 0071 · Allowlisted diagnostics and imported artifact retention

Status: Accepted for P6-04 (2026-09-25).

The Python Host is the sole owner of diagnostics about business state and imported artifacts. `diagnostics.prepare` constructs an allowlisted `forge-diagnostics/v1` object from runtime version/protocol, SQLite health/schema, aggregate counts, and retention metadata. It does **not** scan or export logs, project paths, source, environment variables, credentials, artifact contents, or authentication files. Missing aggregate usage is explicitly `unavailable`, not zero or an estimate. Host JSON-RPC accepts only `prepare` and an exact `cleanup` input; unknown diagnostics methods are rejected.

Electron Main stores the strictly parsed preview in memory for ten minutes. The Settings page displays the exact JSON string that Main later writes after an explicit native Save dialog. Renderer supplies only the preview ID; it cannot choose arbitrary file contents or write a path through the bridge. The export writer refuses a symlink and caps output at 16 KiB. Main invalidates the prepared export when the Host disconnects. The ordinary Web entry has no local diagnostics capability.

The existing SQLite `imported_artifacts` rows were immutable. Additive migration 30 preserves all existing content on upgrade, creates `imported_artifact_tombstones`, and narrows the update trigger to permit only an empty content blob after a same-transaction tombstone. All metadata and historical references remain; arbitrary update and delete stay rejected. The 30-day retention applies only to Host-imported verifier artifacts. No automatic purge occurs. `prepare` snapshots up to 500 expired artifact IDs; `cleanup` requires that unexpired, single-use preview ID plus an explicit Desktop native confirmation. The Host rechecks age and tombstone state in a transaction before clearing bytes. It never accepts a filesystem path for cleanup or touches the user's source repository/worktrees. Active run artifacts and other storage classes have no new deletion policy here.

Real isolated macOS arm64 SQLite tests covered v29→30 migration, old/new content, confirmation rejection, one-shot cleanup, tombstone readback after restart and source Git preservation. Real Electron used a disposable Host data directory containing a token-bearing log and a project path; the full preview matched the exported JSON bytes and contained neither. This proves T115 in the current development build. T111–T114 require signed installer/update, credential migration or active-Run lifecycle work in P6-05–08. T084's current private-key import/diff/export paths are protected; future artifact export and broader sensitive-output cases remain for P6-09. No real user data directory migration, installer, Windows or Intel machine was exercised.
