# ADR 0072 · Owned Host, window and tray lifecycle

Status: Accepted for P6-05 (2026-09-25).

Electron Main owns the single Python Host it started. The Host, not Main, owns Agent Run cancellation and descendant process cleanup. A fixed, versioned `system.activity` JSON-RPC method returns counts from real in-memory starting/development/scheduled/review/verify/refiner/owned-process state. Main validates that the total matches these counts; an unavailable Host is **unknown**, never treated as idle. This adds no Renderer process or filesystem capability.

Closing a window or requesting application quit with active work opens a native three-choice dialog: Cancel, Keep running in tray, Stop safely and quit. The prompt explains that background work requires an awake machine/user session and may be interrupted by sleep. Cancel preserves the window and Run. Keep creates an OS tray/menu, destroys only the management window, and leaves the same Host/owned processes alive. Tray Open, app activation and a second-instance event recreate/show the shared Vue management window without starting another Host or Run. Stop asks the Python Host for graceful shutdown; the existing bounded Host controller then waits for owned process cleanup and only terminates its own Host PID after timeout. For an idle Host, closing quits cleanly. If Host activity is unavailable, the app offers Cancel or Quit, with no claim that work was safely stopped. Suspend/resume changes the tray tooltip and never invents Run state.

The real macOS arm64 Codex long-command fixture observed `command.started`, canceled the first close, kept the Host alive without a window, launched a second Electron instance, reopened on the original Host PID and same running Run, then selected safe quit. The owned Python Host and Codex app-server PIDs exited, and the source Git worktree remained clean. The native dialog buttons/title/detail were asserted; the tray icon was created by the real Main path. An initial repeat of the fixture stalled because the *test harness* registered the second process `exit` listener after it had exited; the listener is now attached before waiting for the reopened window. Only exact PIDs created by that fixture were cleaned up. A degraded Host with corrupt SQLite still answers activity (zero in the isolated smoke), allowing clean exit; a crashed Host asks explicitly. The standard Desktop smoke and full quality checks passed afterward.

T001 retains existing fixed-bridge/forged-sender evidence; T002 and T114 have current real active-Run lifecycle evidence. T003's force-crashed Renderer, T004's formally packaged Mac/Windows shortcut matrix, and T005's physical Windows DPI/board scroll are still `DEFERRED_VERIFICATION` to P6-09/P6-07. Windows tray/notification behavior, Mac packaged tray resources, physical system suspend and installer lifecycle are unverified. Tray PNG assets are included in the source tree; package-resource placement belongs to P6-06/07.

Electron's [Tray](https://www.electronjs.org/docs/latest/api/tray), [app quit events](https://www.electronjs.org/docs/latest/api/app), and [powerMonitor](https://www.electronjs.org/docs/latest/api/power-monitor) APIs were checked on 2026-09-25.
