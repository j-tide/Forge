# ADR 0075 — Offline update integrity and SQLite migration rehearsal

Date: 2026-09-25
Status: Development preflight implemented; installed update acceptance blocked

## Decision

The Python Host package owns `forge.update_preflight`, an offline boundary for future installer/adapters. A bounded `forge-release/v1` manifest must be Ed25519-signed by a separately provisioned trusted public key; verification authenticates the **exact manifest bytes** before accepting required protocol/product fields, semantic version, platform/architecture, artifact name, size and SHA-256. A missing or invalid trust root/signature, incomplete signed manifest, tampered artifact, wrong platform or non-forward version fails closed with a stable path-free error. No public trust root or signing private key has been created or bundled. The local test key is disposable and only proves verifier behavior; it cannot authorize a real Forge release.

After a caller supplies a verified artifact and reports zero active operations, `rehearse_migration` uses Forge Persistence's SQLite online backup, copies committed WAL state into an isolated Forge-owned staging directory through SQLite's backup API, migrates **only that copy**, then checks schema version, `quick_check` and foreign keys. The original database is unchanged. A failed or interrupted rehearsal retains the original data and its backup; no live database is swapped or restored automatically. This is intentional until a signed installer can stop the Host, own an exclusive cutover, prove sidecar/lock state and provide a tested rollback. Staged directories are diagnostic artifacts, not automatically deleted user data. Source database and project Git files are never reset or deleted.

P6-08's independent integrity, version gate, active-Run drain refusal, WAL backup, v29→v30 rehearsal, failure containment and restart behavior are tested on isolated SQLite and ephemeral signature fixtures. This does **not** establish a signed installed-app update, credential continuity, automatic update download, real Host process drain before package replacement or rollback of a production cutover. T086–T090 have existing P3 migration tests and current preflight evidence; T112/T113 and complete P6-08 public acceptance remain deferred. P6-08 therefore remains **BLOCKED**, not DONE. P6-09 can run only current-platform/applicable acceptance through a separately bounded development exception; no public release follows.

`cryptography==50.0.1` was already locked transitively and is now an exact direct dependency for Ed25519 verification. It carries `Apache-2.0 OR BSD-3-Clause` licensing; Python 3.12/macOS arm64 verification is real, Windows wheel/runtime remains untested. No package signing credential, network update server, new renderer permission or second Executor was introduced. Primary documentation checked 2026-09-25: [Ed25519 verification](https://cryptography.io/en/stable/hazmat/primitives/asymmetric/ed25519/) and [PyPI package/version/license](https://pypi.org/project/cryptography/50.0.1/).
