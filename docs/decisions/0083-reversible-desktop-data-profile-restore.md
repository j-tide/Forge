# ADR 0083 — Reversible Desktop data profile restore

Date: 2026-09-26
Status: Internal Desktop implementation; macOS arm64 installed-app profile-switch acceptance passed

## Decision

Forge Desktop may inspect a user-selected **standalone SQLite backup** through its bundled Python runtime, then copy and migrate it into a new UUID-named profile under Forge's own app-data directory. Main owns the native picker, confirmation, pointer and Python Host lifecycle. Python owns SQLite inspection, backup copying and migration. The existing `production` data set and any earlier restored profiles are never replaced or deleted. This is a local data-profile selection, **not** an installed application update or a production database file swap. ADR 0075's signed update and installer cutover gate remains unchanged.

Before switching, Main rejects active Host work, stops accepting new Renderer commands, drains in-flight Host requests, checks activity again, and waits for its owned Host to exit. A versioned, fsynced pointer changes only after staging is valid. Main starts the selected profile and rolls the pointer back if that Host cannot start. Invalid or missing pointer targets refuse Desktop startup rather than silently opening a different data set. No arbitrary database path, SQL, file reader or child-process control crosses Preload. Dev Desktop cannot switch production data profiles.

### Durable recovery fence · 2026-09-27

In-memory activity is insufficient after a Host crash: an interrupted Run, quarantined workspace lease, interrupted Review/Verify or old process journal record may still represent a writer, even when the new Host has no live task. The Python Host now answers one fixed, read-only `system.profileSwitchSafety` method with bounded aggregate counts and a `safe` result. It does not return raw PIDs, paths, tokens or SQL to the Renderer. Main requires both zero current activity and the durable safety result before staging and again after quiescing, while the same owned Host and selected profile are still active. Recovery uncertainty returns `RUN_RECOVERY_REQUIRED` without moving the profile pointer, stopping Host, deleting old data or signaling a historical PID. The UI explains why switching is refused. This is an additive local protocol-v5 method; no migration, network method or generic IPC was added. It intentionally may block a user until the existing recovery evidence can be reconciled safely.

The first scanner only counted parseable old process records. A torn `.tmp` write, malformed JSON, symlink or unexpected journal entry could therefore be skipped and falsely yield `safe=true`. The Host now reports `uncertainProcessJournalEntries` separately and refuses a profile switch when it is nonzero. It scans the Forge-owned journal directory without following links and validates bounded record identity before treating an entry as known. This never treats a journal record as proof that a process is still alive or safe to kill. An isolated installed app using a malformed journal refused the normal Settings restore and preserved Host/profile/backup; cleanup of the planted test file was limited to that disposable QA directory. Windows/Intel and physical native-dialog behavior remain unverified.

## Imported authority

A selected backup may contain trust decisions and device sessions made on another machine. The staged copy therefore changes every saved Project to `project-trust/restored-pending`, retaining its history but blocking code access and execution. The user must select the directory again through Desktop, review a fresh read-only probe and explicitly trust it. The existing Project ID and task history remain stable; a compare-and-swap revision prevents stale approval. Existing paired devices and sessions are revoked, and unfinished pairing challenges expire in the staged copy. The source backup and original data set are unchanged. Restoring data never grants new local project trust or remote authority.

## Boundaries and limits

The SQLite backup contains metadata, messages, Tasks and Run records. It does **not** contain project source, isolated worktrees, imported artifact files, external Codex authentication or credentials. Historical evidence may therefore point to unavailable files. No missing artifact is synthesized. A restored profile is not a complete machine migration. The native confirmation lists schema and Project/Task/Run counts before switching, and Settings offers return to the original data set. A rollback pointer preserves both data sets; it cannot reverse actions the user later performs within either one.

This internal action does not establish signed updater integrity, Developer ID/notarization, Windows/Intel behavior, live active-Run restore, or full release acceptance. Those gates remain tracked separately.
