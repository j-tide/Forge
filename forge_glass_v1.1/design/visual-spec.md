# Forge UI 1.1 · Frosted Workspace

状态：等待用户确认的视觉方向稿。日期：2026-09-23。

## 01 / 从参考视频提取的设计语言

参考是本次对话提供的 26.54 秒视频。已查看整体及多个时间点，而非只根据文件名判断。

- 约 8–14 秒：浅蓝银白的整体磨砂容器、窄图标侧栏、柔和卡片、深色小胶囊按钮。
- 约 16–20 秒：低对比浮雕圆环，仅承担装饰；阅读内容保持平整。
- 约 23–26 秒：主内容与辅助卡片分层，转场轻柔，不靠强烈发光突出交互。

本稿借鉴材质、圆角、层次和动效节奏，不复制原视频品牌、文案、Windows 壁纸或收费页面。

### 不做

不做高透明大面积透字、彩虹折射、霓虹发光、持续闪烁、黑色重侧栏或铜橙主题。不把每个按钮做成三维玩具，也不把信息密度压缩成只能放两张卡片的展示页。

### 保留的 Forge 产品逻辑

聊天 → 标准化草稿 → 人工审批 → TODO → 开发 → Review → 验证/人工验收 → 完成。

执行器、模型和角色分离；默认流程与自定义编排共存；Forge 与 ProofRun 独立；手机端控制远程 Host，不能冒充本机编程运行时。

## 02 / 视觉构成

### 材质层级

1. 展示环境：本稿自行绘制的蓝银色曲面背景。它只用于展示，不是产品功能。
2. 应用外壳：银蓝偏白、高雾度、强散射的玻璃；默认有足够不透明度，不让背景干扰阅读。
3. 内容容器：比外壳更实的白色表面，薄边高光、宽而浅的阴影。
4. 活动卡片：适度提高亮度；蓝色只用于选中和进度，不给所有卡片都加亮边。
5. 审批/详情：高不透明度阅读面；审批时弱化背景，详情抽屉则保留看板位置感。
6. 代码与日志：优先清晰，使用接近不透明的浅色阅读底，不透出背景纹理。

阴影只用来区分层级。不得同时给外壳、列、卡片、标签、文字堆重阴影。

### 颜色

- 正文：`#242c3e`；主要操作：`#222b3c`。
- 次要正文：`#626d82`；辅助标注适当降低强调，但不能承担唯一的关键状态信息。
- 交互蓝：`#426fd0`；导航选中材质：淡青蓝渐变。
- 成功、警告、风险保留文字和图形，不仅靠绿色/黄色/红色。
- 生产验收必须重新检查真实合成背景上的对比度；本稿没有声称全部文字已满足某一无障碍等级。

### 圆角与空间

应用展示壳 30px；主要面板 24px；任务卡 19–20px；输入框 12px；审批 29px；详情抽屉 25px；胶囊按钮 999px。

侧栏 68px；聊天 298px；工作区左右 25px；卡片间距 12px。1600×1000 主稿能同时容纳五列；较窄窗口保留列宽并在看板内部横向滚动，不能把卡片压到不可读。

页面不应使用整页 transform 缩小来适配窗口。字体跟随平台系统字体，正文和按钮使用明确语义级别；辅助示意标注不应被复制成生产环境的关键正文尺寸。

## 03 / 信息结构的调整

旧稿的多种全页面详情收敛为少量主路由和上下文面板，避免用户频繁失去看板位置。

| 主路由/面板 | 本稿行为 | 实现时注意 |
|---|---|---|
| Board | 左聊天、中看板、下方当前执行条 | 下方执行条只关联选中/固定的 Run，不能代表全部执行 |
| DraftDialog | 中央审批面板，可编辑标题、目标、验收 | 批准不自动开工；合同变更需要新版本审批 |
| TaskDrawer | 右侧展开；需求/活动/变更/检查 | 结果必须绑定对应版本，不以动效完成代替执行完成 |
| Workflows | 左流程，右节点属性 | 配置校验、版本、循环上限仍由 Host 管理 |
| Agents | 角色卡片；插件作为独立页签 | Agent Profile 不等于执行器或模型 |
| Knowledge | 文档/记忆页签，带来源预览 | 候选经验不直接成为业务事实 |
| Projects | 目录、命令与诊断 | 连接项目不自动运行脚本 |
| Devices | Host 与设备权限，手机预览 | 示例在线状态不是真实连接 |
| Settings | 外观、模型、权限、隐私 | 减少透明度和减少动画都必须有 |
| Global Search | 快捷搜索任务 | 不能把查询文本当成执行指令 |
| Mobile Companion | 待办/审批/阻塞入口 | 不是把五列桌面看板硬缩成手机 |

本原型包含七个主路由，以及审批、详情、角色配置、搜索、手机预览五类面板。它重新组织旧稿信息架构，不是对旧版 15 个 Desktop 页面的逐页机械换色。

## 04 / 主要交互与动效

- 页面切换：约 330ms，淡入加 7px 垂直位移；不做大型翻页或三维旋转。
- 卡片 hover：约 200ms，最多上浮 3px；无“磁吸鼠标”行为。
- 审批打开：约 320ms，`opacity`、18px 位移、`scale(.985→1)`；背景为局部模糊遮罩。
- 详情抽屉：约 350ms，右侧进入 30px；不把左边聊天整体推走。
- 新任务：一次性短提示；位置和状态由命令成功的反馈决定，不能提前乐观地显示已执行。
- 导航：淡蓝选中光晕，不循环脉冲。运行状态可用图标/文字提示，而不是持续全屏动画。
- 暂停：请求中与执行器确认后的已暂停，在产品实现中必须区分。本原型只有演示状态切换。
- 减少动画：使用系统偏好或用户选项，关闭位移、缩放，保留瞬时状态变化。[S3]

避免对 `backdrop-filter` 的模糊半径逐帧动画，优先动画 transform/opacity。不得为了演示“60fps”伪造帧率结论；本包视频只是原型实录，不是性能基准。

## 05 / 玻璃材质的跨平台边界

CSS `backdrop-filter` 处理的是元素背后的页面像素，透明或半透明背景才会显示这种效果。它不等于获得读取真实桌面壁纸的能力。[S1]

本稿将蓝色展示环境置于同一网页中，说明材质视觉目标。正式 Electron Desktop 应将系统窗口与页面层分开处理：macOS 可评估官方 `setVibrancy`；Windows 的 `setBackgroundMaterial` 有明确的平台与版本条件（官方当前文档限定 Windows 11 22H2+）。这些不是保证不同平台像素级相同的承诺。[S2]

推荐落地顺序：

1. 先实现所有平台一致、可读的实色/半透明应用内部层。
2. 增加 WindowMaterialAdapter；按操作系统、系统版本、用户透明度偏好与性能探测选择原生材质。
3. 不支持原生背景或出现性能问题时，回退到同色实底，不影响任何业务能力。
4. 使用各平台真实的窗口控件与拖拽区域；不要用本 HTML 的模拟最小化/关闭图标冒充系统实现。
5. 手机 PWA 默认使用轻量、不依赖桌面材质的表面。不要强求各手机浏览器与桌面有相同背景模糊。

尚未完成任何 Windows / macOS 实机窗口材质测试。本原型只在容器 Chromium 中渲染与交互检查。

## 06 / 可读性、键盘与反馈

弹层须有可辨认的标题、关闭操作、Escape 行为、Tab 焦点约束和关闭后的焦点返回。危险动作不可只依赖点击卡片或拖动发生。中文输入法组合输入时 Enter 不应误提交。

本稿实现了上述基础焦点与输入保护，但没有完成全套读屏审计。真正落地时还需检查：原生标题栏可访问名称、放大字体、200% 缩放、选中状态、长任务名、空数据、中文与英文长文本、OS 高对比模式、屏幕阅读器。

任务卡片点击区可以大；编辑和快捷操作不得与打开详情产生冲突。对比度测试应覆盖明暗桌面、关闭透明度模式、模态叠层和代码差异的增删颜色。
