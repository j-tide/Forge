# 后续扩展，不混入v1.0

| 扩展 | 开始条件 | 实现边界 | 必须证明的收益 |
|---|---|---|---|
| 多任务并行 | 单任务恢复与租约可靠 | 每任务独立worktree；同一任务单写入者 | 吞吐提升不增加错误合并 |
| 工作流fan-out/join | 编译器和产物版本稳定 | 优先并行只读审查；并行写必须独立树+集成节点 | 提速、冲突成本可测 |
| 第三方插件 | 公开API稳定、权限可落实 | 独立插件进程/签名/来源/撤销；不是任意npm运行 | 升级不破坏核心 |
| RAG向量混检 | 有项目标注集与基线 | 先范围过滤、去重、RRF；离线证据与原文绑定 | 检索正确率与任务结果改善 |
| 受控自进化 | 固定评测、反馈数据足够 | 经验→候选patch→离线对照→人审→有限新Run→回滚 | 减少误完成/人工介入，不只提高通过率 |
| Codex App Server适配器 | 官方稳定性/版本探测满足需求 | 独立adapter；不暴露原始服务给手机 | 相比SDK确有需要的能力 |
| Capacitor原生手机包 | PWA真实使用暴露需求 | 共用业务UI，补推送/生物识别等桥接；不是手机跑CLI | 必要原生体验明确 |
| Linux/NAS Headless Host | Desktop Host完全去Electron依赖 | 独立凭据保管、进程管理、升级与运维文档 | 常在线远控确有需求 |
| 公网Relay/多人协作 | 私网单Owner远程稳定 | 单独威胁模型、身份、租户、审计与运营 | 权限清晰与可管理性 |
| 外部验证产品接入 | 独立产品接口与授权确定 | 通过通用Verifier插件，当前不依赖任何独立测试项目 | 不侵入Core且产物可追溯 |

## 自进化的具体发布流程

收集经过确认的任务失败、Review误报、循环返工和人工纠正。按类型聚类，先区分模型能力、工具错误、上下文不足、业务歧义。候选只能改变允许的角色提示词片段、上下文检索权重、重试预算或测试优先策略，不允许改安全政策、权限或已批准合同。

每个候选记录来源Run、预期收益、适用项目/角色、反例、旧策略hash和候选hash。开发集用于改进，保留集只做最终验证；同模型/预算/仓库快照多次比较，记录成功率、误Done、总成本与人工次数。数据不足时标“无结论”，不能用最好一次发布。

人类批准后只分配到少量新Run，冻结旧Run策略；自动监控错误Done、失败、成本或安全告警，任何关键退化停用候选。回滚保留已发生事件，不能改历史报告。体验记忆不是底层模型训练，也不是无人工监督的源代码自修改。
